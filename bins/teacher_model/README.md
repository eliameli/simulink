# Модель БИНС преподавателя — рабочая копия

Эту модель прислал преподаватель для учебного курса по БИНС. Задача —
разобрать её по теории (В.В. Матвеев, «Инерциальные навигационные
системы»), проверить на идеальных данных, затем подать в неё мои реально
записанные данные (см. `../phoneA/`, `../phoneB/`).

## Как запускать

**ВАЖНО: на машине, где я (Claude) это разбирал, MATLAB не установлен.**
Всё написанное ниже — из чтения текста `.mdl`-файла (это обычный текстовый
формат, не бинарный) и встроенного в него Stateflow-кода MATLAB Function
блоков. Ничего из этого НЕ проверено запуском. Нужно самостоятельно
открыть `bins_model2.mdl` в MATLAB/Simulink и подтвердить всё ниже.

1. Открыть `bins_model2.mdl` в MATLAB (требуется **Aerospace Blockset** —
   см. ниже, почему).
2. Запустить (Run). Время моделирования 0–300 с, решатel `ode45`
   (переменный шаг).
3. Два похожих блока на верхнем уровне, `BINS` и `BINS1`, — это, судя по
   всему, **идеальный** (без датчика) и **реалистичный** (через модель
   ИИМ) варианты алгоритма, считающиеся параллельно для сравнения
   (see "Находки" ниже, не до конца проверено — это уже вопрос шага 3).

## Структура папки

```
bins_model2.mdl          — основная модель (выбрана из нескольких
                            кандидатов, см. обсуждение ниже)
f_*.m                     — функции, которые реально вызываются внутри
                            bins_model2.mdl (проверено по встроенному
                            коду MATLAB Function блоков, не угадано)
```

Файлы, не нужные выбранной модели (`BINS.mdl`, `bins_model.mdl`,
`bins_model_with_aerospace.mdl`, `motion_model.mdl`, `model_bins.slx`,
`bins_model2_with_c_code.mdl` и неиспользуемые `f_*.m`/`c_*`) были
удалены из рабочей копии по моей просьбе. Они не потеряны — лежат в
истории git на этой ветке, в коммите `c60a60d` (папка `_unused/`) и
раньше. Восстановить: `git checkout c60a60d -- bins/teacher_model/_unused`.

### Что нужно `bins_model2.mdl` (проверено по встроенному коду блоков)

| Файл | Где используется |
|---|---|
| `f_normalize_angle.m` | блоки "normalize angles" (×2 — в BINS и в BINS1) |
| `f_calc_turn_matrix_from_angles.m` | блоки "calc rotation matrix" (×2) |
| `f_turning_by_Euler.m` | блоки "Turning equations" (×2, кинематика Эйлера) |
| `f_calc_ang_vel.m` | блок "calc angular velocity" (в модели эталонного движения) |
| `f_calc_ang_accel.m` | блок "calc angular acceleration" (в модели эталонного движения) |
| `f_angles_diff.m` | блоки "Angles difference" (сравнение эталона и БИНС) |
| `f_motion_model2.m` | блок "Motion model 2" (генератор эталонной траектории) |

Проверено так: в `.mdl`-файле каждый блок "MATLAB Function" хранит свой
код прямо внутри файла (секция `Stateflow { chart { ... script "..." } }`).
Я прочитал текст всех 17 таких блоков и выписал, какую именно функцию
каждый вызывает — это не предположение по именам файлов, а прямое чтение
вызовов `fcn(...)`.

**Параметры модели движения — не ищите workspace-переменные, их нет.**
Амплитуды, периоды и фазы Лиссажу-траектории (`A`, `T`, `Fi`), начальные
условия (`du0_dt`), гравитация и центр масс — все заданы прямо в
параметрах `Constant`-блоков внутри самого `.mdl`, а не через `InitFcn`
или `.mat`-файл. `InitFcn`/`PreLoadFcn`/`StopFcn` в свойствах модели —
пустые, ничего не задают.

### Важная находка: модель требует Aerospace Blockset

Блок "Three-axis Inertial Measurement Unit" (питающий, судя по всему,
один из двух параллельных трактов, `BINS1`) — это **не собственный код
преподавателя**, а готовый блок из библиотеки `aerolibnav` (Aerospace
Blockset). Без установленного Aerospace Blockset модель не откроется
целиком (Simulink будет жаловаться на недостающую библиотеку). Это нужно
сказать преподавателю / проверить у себя заранее.

### Почему остальные файлы были отложены (сейчас удалены, см. выше)

- `BINS.mdl` — отдельный "чистый" блок БИНС без модели движения и без
  ИИМ (входы прямо `a`, `w`, начальные `r`/`v`/`angles`). Не используется
  `bins_model2.mdl`, но, вероятно, пригодится отдельно на шаге 6 (подать
  туда реальные данные напрямую, без генератора траектории) — **если
  понадобится, восстановить именно этот файл командой выше**, когда
  дойдём до этого шага.
- `bins_model.mdl`, `bins_model_with_aerospace.mdl`, `motion_model.mdl`,
  `model_bins.slx` — более ранние версии/черновики (по датам изменения
  старше `bins_model2.mdl`), другая, менее полная структура.
- `bins_model2_with_c_code.mdl` — та же модель `bins_model2`, но новее
  (2019 vs 2017) и с альтернативной C-реализацией одного блока
  (переключаемой вручную). Отложена по вашему выбору — для разбора по
  книге достаточно чистой MATLAB-версии.
- `f_motion_model.m`, `f_turning_by_Euler2.m`, `f_turning_by_Euler_c.m`,
  `c_turning_by_Euler.cpp`, `c_turning_function_by_Euler.c`,
  `rtwmakecfg.m` — альтернативные/более старые реализации тех же формул,
  которые `bins_model2.mdl` не вызывает (проверено чтением кода, не
  угадано).
- `p_plast1.m` — тестовый скрипт, вызывает функцию `f_motion_params`,
  которой в присланном архиве нет. Похоже на нерабочий черновик.
