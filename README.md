# GPS-free навигация: dead reckoning + привязка к карте (Simulink, v0)

Учебный проект: имитация инерциального датчика (акселерометр + гироскоп)
на движущемся по дорожной сети автомобиле, восстановление траектории по
показаниям датчика ("dead reckoning") и привязка восстановленной
траектории к известной карте дорог **без использования GPS**.

## Идея проекта (по заданию)

Проект состоит из двух независимых частей:

1. **Часть 1 — генератор эталона + карта + модель датчика.**
   Скрипты строят синтетическую дорожную сеть (карту), а маршрут
   автомобиля по ней вы задаёте сами — рисуете его мышью прямо на
   карте, зажав левую кнопку и проведя по маршруту (`map/pick_route.m`).
   Машина едет через получившиеся точки с одной постоянной
   скоростью (без разгона/торможения — только курс меняется на
   поворотах), это и есть эталонная (истинная, точная) траектория. Из
   неё считаются "истинные" ускорение/угловая скорость, которые идут на
   вход Simulink-модели. Внутри модели блок датчика превращает их в
   *измеренные* (зашумлённые) значения — с учётом типичных ошибок
   MEMS-датчиков: шум и смещение (bias), которое ещё и медленно
   "плывёт" во времени (bias random walk).
2. **Часть 2 — навигация без GPS.**
   По зашумлённым показаниям датчика Simulink-модель восстанавливает
   положение автомобиля методом счисления пути (dead reckoning),
   интегрируя не методом Эйлера, а методом Рунге-Кутты 4-го порядка
   (RK4). Это даёт **красную** траекторию. Сама по себе она неизбежно
   "уплывает" от истинной, но блок `INS Mechanization` умеет отличать
   настоящий поворот (десятки-сотни град/с) от шума и смещения датчика
   на прямом участке (доли град/с) и в конце каждого распознанного
   поворота подтягивает текущее положение к ближайшему перекрёстку
   (не мгновенным телепортом, а на 70% пути к нему) и довыравнивает
   курс по той дороге от этого перекрёстка, что ближе всего к текущему
   направлению. Коррекция срабатывает не чаще раза в секунду и только
   если ближайший перекрёсток реально близко (иначе, если оценка уже
   далеко улетела, "магнититься" не к чему) — это защищает от того,
   чтобы один и тот же реальный поворот (особенно если маршрут
   нарисован мышью не идеально ровно и распадается на несколько мелких
   поворотов подряд) не срабатывал по нескольку раз подряд. Отдельно
   первые несколько секунд (пока ни один поворот ещё не успел
   произойти и корректировать нечего) красная траектория держится на
   дороге постоянно, а не по событию поворота — иначе шум/смещение
   датчика может увести её в сторону ещё до первого реального
   перекрёстка. Дальше блок привязки к карте (map matching) на каждом
   шаге ещё и
   проецирует эту траекторию на ближайший отрезок дороги (плюс
   гистерезис, чтобы не дёргаться между соседними дорогами у
   перекрёстка) — это даёт **синюю** (финальную) траекторию.

   Всё это — без GPS, только по карте и показаниям датчика.

Это **нулевая версия (v0)**: карта — синтетическая (не настоящий OSM),
привязка к карте — самая простая (проекция на ближайший отрезок дороги,
без учёта истории движения). Это сделано специально, чтобы сначала
проверить концепцию целиком на простом примере, а потом усложнять
отдельные части (см. раздел "Куда развивать дальше").

## Структура репозитория

```
map/
  generate_map.m          - строит синтетическую дорожную сеть (граф: nodes+edges)
  pick_route.m            - маршрут: тянете мышью (зажав кнопку) по карте -> точки через
                            равные ~25 м вдоль пути, независимо от скорости ведения мыши
  plot_map.m              - отрисовка карты
truth/
  generate_trajectory.m   - строит эталонную (истинную) траекторию по точкам маршрута
                            (постоянная скорость, повороты на промежуточных точках)
sim/
  unicycle_rk4_step.m     - RK4-шаг кинематической модели автомобиля (общая логика)
  map_match_nearest.m     - привязка точки к ближайшему отрезку дороги (справочная copy)
  sensor_params.m         - параметры модели ошибок акселерометра/гироскопа
  build_model.m           - программно строит Simulink-модель gps_free_nav_v0.slx
  run_v0.m                - главный скрипт: карта -> эталон -> модель -> симуляция -> графики
  blocks/
    ins_mechanization_block.m  - блок "INS Mechanization (RK4)" -> красная траектория
    map_matching_block.m       - блок "Map Matching" -> синяя траектория
models/
  (сюда build_model.m сохранит gps_free_nav_v0.slx при первом запуске)
```

Модель `.slx` не лежит в репозитории в готовом виде — она **генерируется
локально** скриптом `build_model.m` (у меня нет MATLAB, чтобы собрать и
проверить бинарный `.slx` файл; зато .m-скрипты, которые её строят,
можно читать, проверять и версионировать в git как обычный текст).

## Как запустить

В MATLAB R2024a:

```matlab
cd sim
run_v0
```

Скрипт сам:
1. сгенерирует карту;
2. откроет окно с картой и попросит вас **нарисовать маршрут** —
   зажмите левую кнопку мыши, проведите по маршруту, отпустите кнопку,
   когда закончите;
3. по нарисованной линии построит эталонную траекторию (постоянная
   скорость, повороты в точках изгиба маршрута);
4. заново соберёт `models/gps_free_nav_v0.slx` (пересобирается каждый
   раз, чтобы не подсовывать случайно устаревшую версию модели);
5. запустит симуляцию;
6. построит графики: карта + истинная траектория (чёрная) + "поплывшая"
   dead-reckoning-траектория (красная) + траектория после привязки к
   карте (синяя), плюс график накопленной ошибки во времени для обеих
   оценок.

### Если сборка модели даст сбой на каком-то блоке

`build_model.m` создаёт два блока MATLAB Function программно (через
Stateflow API) — это единственная "хрупкая" часть скрипта, которую я не
мог проверить без MATLAB. Если при сборке появится предупреждение по
конкретному блоку, откройте модель, дважды кликните на пустой блок и
вставьте код из соответствующего файла в `sim/blocks/` вручную — там
лежит ровно тот код, который скрипт пытается вставить автоматически.

## Что учитывается в модели ошибок датчика (v0)

Для акселерометра и гироскопа отдельно (см. `sim/sensor_params.m`):

- **bias0** — постоянное смещение "при включении" (turn-on bias);
- **bias random walk** — смещение медленно "плывёt" во времени
  (реализовано как белый шум, пропущенный через интегратор);
- **white noise** — обычный измерительный шум на каждом шаге.

Это упрощённая, но содержательная модель типичных ошибок MEMS-датчиков
(без имитации конкретного датчика по даташиту — цифры условные,
порядка типичных потребительских IMU).

## Куда развивать дальше (v1+)

- Заменить синтетическую карту на настоящие данные (OpenStreetMap /
  Automated Driving Toolbox `drivingScenario`, если появится лицензия).
- Привязка к карте сейчас — "ближайший отрезок + гистерезис" (не
  переключается на другую дорогу, пока она не ближе на заметный запас —
  см. `sim/blocks/map_matching_block.m`), это убирает дёрганье между
  соседними дорогами у перекрёстка, но полноценной памяти о маршруте
  всё ещё нет. Следующий шаг — привязка с учётом истории движения
  (например, Hidden Markov Model по графу дорог, либо частичный
  фильтр/Particle Filter) — устойчивее к шуму и развилкам.
- Добавить разгон/торможение (сейчас v0 намеренно упрощена до одной
  постоянной скорости — см. `truth/generate_trajectory.m`).
- Объединить dead reckoning и map matching через фильтр Калмана
  (коррекция оценки, а не жёсткое "прилипание" к дороге).
- Если появятся Navigation Toolbox / Sensor Fusion and Tracking Toolbox
  — заменить самодельный блок датчика на `imuSensor`, а мехенизацию — на
  `insfilterMARG`/`insfilterAsync`, сравнить с самодельной реализацией.
